# Analyzing GCaMP afferent activity: baseline vs. post-optostim

**Experiment this covers:** awake 2P imaging (Scanbox, single plane) of ChR2+GCaMP-expressing afferents. Paradigm: baseline recording → ~1 h optostimulation with no imaging → post recording. Question: did the optostim change afferent activity? No stim–frame synchronization exists yet, so this is a comparison of *spontaneous* activity between the pre and post sessions — not a trial-aligned analysis.

## The short answer

Yes, you need registration, and yes, AQuA2 is a reasonable next step — but the critical part of this analysis is not the event detector, it's (1) getting pre and post into the same coordinate frame, (2) running detection with *identical* parameters on both, and (3) controlling for the confounds that come with an awake animal and a 1+ hour gap (locomotion state, z-drift, bleaching). The steps below follow the lab's existing code where possible.

## Step 1 — Unpack (done)

`UnpackSBX.m` extracts each .sbx run to .tif and writes mean projections. For single-plane data it takes the 2D branch (`WriteSbxPlaneTif` + `WriteSbxProjection`); no `FixSBX`/dewarping is involved until you move to optotune volumes later.

## Step 2 — Registration: required, and use the concat-first version

Registration is not optional for this experiment, for three reasons. First, the animal is awake: brain motion of even 1–2 pixels is larger than an axon's diameter, so unregistered movies produce garbage traces. Second, AQuA-style event detectors interpret motion as signal — a shifting bright axon creates false "events" along its edges, and that artifact will not be equal between a calm baseline and a possibly-aroused post session, biasing your pre/post comparison. Third, and most important for your design: to say "the *same* afferents became more/less active," baseline and post movies must be registered to one common reference. That is exactly what `ProcessScanboxData_concatFirst.m` does — it concatenates the runs *first* (`ConcatenateRuns`), picks one reference from a still period (`DetermineReference`, using the locomotion data), and registers the whole concatenated movie to it. So: put both the baseline run(s) and the post run(s) on the same row/experiment in the data spreadsheet and process them together, not separately.

Settings: use `dataSet = 'Afferents'` (green reference channel). The defaults specify affine registration; the script currently overrides it to rigid — rigid is a fine starting point and less likely to invent deformations; switch to affine only if the registered movie still shows slow stretching/shearing. Pick the reference from a quiescent stretch of the *baseline* session.

**One check registration cannot fix: z-drift.** Over the stim hour the plane can drift axially, and in single-plane data no algorithm can recover that. Before analyzing anything, open the per-run mean projections the pipeline writes and visually compare baseline vs. post. If the same axons/branch points are visible in both, proceed. If the field looks different (axons gone, new ones appeared, focus changed), the "same afferents" comparison is invalid for that session — you can only compare FOV-level activity with heavy caveats, or exclude the session. Consider making this an explicit QC step (e.g., cross-correlation of the two mean images) for every experiment.

## Step 3 — Prepare the AQuA2 input

`GenerateExptProjections` writes cropped, downsampled per-run movies from the registered data; these are the natural AQuA2 input. One parameter deserves scrutiny: the afferent preset targets **1 Hz**. Axonal GCaMP transients typically last only ~0.5–2 s, so at 1 Hz many events span 1–2 frames — frequency counts survive, but amplitude and duration estimates get unreliable and small events can vanish. Since your entire readout currently rests on this spontaneous-event comparison, consider a gentler downsample (e.g., to ~5–7 Hz from Scanbox's native ~15.5 Hz) by raising `projParam.rate_target`. Whatever you choose, use the same value for every session and animal. Keep the green channel, keep the edge crop (removes registration artifacts at borders).

AQuA2 accepts .tif input (including >4 GB), runs in MATLAB (R2022b+ recommended), and has both a GUI (`aqua_gui.m`) and a batch mode (`aqua_cmd_batch.m`) driven by a CSV of parameters.

## Step 4 — Run AQuA2 identically on pre and post

Tune parameters once, in the GUI, on one representative *baseline* movie: intensity threshold, smoothing, minimum event size, temporal cut. Proofread visually — confirm detected events sit on axons and track real transients, and that motion residue at bright edges is not being called events. Then freeze those parameters and run everything (baseline + post, all animals, experimental + control) through batch mode with the same CSV. Never tune per-condition — if pre and post are detected with different thresholds the comparison is meaningless. Detecting on the concatenated registered movie in one AQuA run (then splitting events by frame index into pre/post) is an even cleaner way to guarantee identical treatment, since the pipeline already gives you the concatenation frame boundaries (`expt.scanLims`).

## Step 5 — Quantify and compare

From AQuA2's event tables, the metrics that answer "did optostim do anything":

- **Event frequency** — events per minute, at the FOV level and (if the same axons are identifiable) per axon/CFU. Normalize by recording duration.
- **Event amplitude (dF/F), area, and duration** — distribution shifts pre → post.
- **Active fraction** — proportion of the axon-covered field showing any event.

Statistics: treat the animal (or FOV) as the unit, paired pre vs. post; then compare the pre→post *change* between ChR2 mice and controls. That control group is essential here, because two things change over an hour regardless of opsin activation: **bleaching/expression drift** (lowers apparent activity post) and **arousal/behavioral state** (locomotion strongly drives afferent activity, and an animal that just experienced an hour of stimulation may behave differently). The pipeline already extracts locomotion (`GetLocoData`, `GetLocoState`, `PeriLoco`) — use it: either restrict the pre/post comparison to quiescent (still) periods only, or report loco-matched epochs, and report time-spent-moving in both sessions so a reviewer can see the states are comparable. A light-delivered, opsin-negative control (same GCaMP, same fiber illumination) also rules out heating/visual effects of the stim light itself.

## Step 6 — Sanity check with plain ROI ΔF/F

Before trusting event statistics, hand-draw ROIs over 5–10 clearly visible axon segments on the registered mean projection, extract raw traces across the concatenated movie, and look at them. If AQuA reports a big frequency increase but the raw traces look identical pre/post, the parameters are off. This one afternoon of validation protects the whole result.

## Is AQuA2 the right tool at all?

For this specific question it is defensible, and staying with it keeps you comparable to the lab's previous afferent data. Its strengths for axons: no ROI curation (axon segmentation is genuinely hard — Suite2p's detection is soma-shaped), and it captures spatially extended events propagating along an axon. Its weaknesses: sensitivity to detection parameters and residual motion, and event-based statistics are less standard than trace-based ones. Note the lab already has a parallel Suite2p route (`UnpackSBX_multi_suit2p.m` to prepare data, and `GCAMP_concat_Fall.m`, which exists precisely to concatenate two recordings' Suite2p outputs plus locomotion plus event tags — i.e., someone has done a pre/post GCaMP comparison with Suite2p before). A reasonable long-term position: AQuA2 for the spontaneous pre/post analysis now, cross-validated with the ROI check, and when frame-synced optostim is working, move the primary analysis to stim-triggered ΔF/F on ROIs — that will be a far more direct and sensitive test of whether stimulation activates these afferents than any pre/post spontaneous comparison can be.

## Caveat on interpretation

A pre/post design with an hour gap can only show *persistent changes* in spontaneous activity (sensitization, depression, plasticity). A null result does not mean the opto failed to activate the afferents — they may respond robustly during stimulation and return to baseline within minutes. Worth stating explicitly in any lab meeting: the current paradigm tests after-effects; the synchronized-imaging project tests activation itself.

## Checklist

1. UnpackSBX per run (done).
2. Add baseline + post runs as one experiment in the spreadsheet; run `ProcessScanboxData_concatFirst` (Afferents preset, rigid to start, reference from still baseline period).
3. QC: compare pre/post mean projections for z-drift; exclude or caveat drifted sessions.
4. Generate projections (consider ~5 Hz rather than 1 Hz; same for all data).
5. Tune AQuA2 in GUI on one baseline movie; proofread.
6. Batch-run all movies with frozen parameters (or run once on the concatenated movie and split by frame).
7. Compare event frequency/amplitude/area pre vs. post, within matched locomotion state; animal-level paired stats; compare change vs. opsin-negative controls.
8. ROI ΔF/F sanity check on a handful of axons.

## Addendum: tool choice, independent of legacy comparability (added after literature check)

If comparability with old lab data is not a constraint, the strongest literature precedent for this exact preparation is an **ROI-based, per-fiber analysis**, not event-based AQuA. The published meningeal/trigeminal afferent imaging papers from the Levy–Andermann lineage (Blaeser et al., Cell Reports 2022; Blaeser et al., eLife 2024) used: affine/TurboReg registration (essentially this lab pipeline) → PCA/ICA extraction of correlated-pixel ROIs with manual curation → hierarchical clustering of ROIs (activity correlation > 0.7 during quiet wakefulness) into individual afferent fibers → ΔF/F with a moving 10th-percentile baseline → threshold-based event detection (z > 1 for ≥ 1 s, peak ΔF/F ≥ 5%) → GLMs against locomotion and meningeal deformation. That workflow yields per-afferent statistics (fraction of responsive fibers, per-fiber event rate/amplitude changes), which is the readout reviewers in this field expect and maps directly onto "did optostim change the activity of these afferents."

Where the three candidate routes stand: AQuA2 (Mi et al., Cell 2025) is designed for signals *without* fixed sources — astrocytes, ATP, spatially propagating events — and is the right tool when you cannot define ROIs; its costs are parameter sensitivity and statistics that attach to events rather than to identified afferents. Suite2p works on axons/boutons with adjusted settings, and the recent SUBPREP toolbox (Parasar & Chettih et al. lineage, eNeuro 2025) builds exactly this out for subcellular data: Suite2p ROIs plus frequency-based ROI screening, z-motion artifact rejection (a real issue for a pre/post design with a 1 h gap), and correlation-based clustering of ROIs into axons. The PCA/ICA + clustering route is what the published afferent papers actually used and parts of it likely already exist in the lab.

Practical recommendation: keep the registration front end unchanged; make an ROI-based per-fiber analysis the primary readout (Suite2p+SUBPREP-style, or the lab's PCA/ICA route), with per-fiber event frequency/amplitude compared pre vs. post within matched locomotion state; AQuA2 becomes an optional secondary analysis rather than the backbone.

## Addendum 2: mCitrine (ReaChR tag) co-expressed in the green channel

The afferents co-express ReaChR-mCitrine along with the GCaMP, and mCitrine's emission (~529 nm) is inseparable from GCaMP's (~512 nm) with a single green PMT — so the recorded green signal is F(t) = GCaMP(t) + static mCitrine. Consequences:

**Use it as a free structural channel.** A pixelwise low-percentile projection over time (5th–10th percentile of each pixel across the movie) approximates the static fluorescence — mCitrine plus resting GCaMP — and shows the opsin-expressing afferents even when they are silent. Use this image to (1) define/curate ROIs so silent fibers are included, giving a true denominator for "fraction of afferents that changed"; (2) QC pre-vs-post z-drift (compare the two low-percentile images); (3) confirm the registered movie is stable.

**It biases ΔF/F₀, with a directional pre/post confound.** The static mCitrine inflates F₀, compressing ΔF/F amplitudes; worse, mCitrine (a YFP) photobleaches, so if F₀ drops between baseline and post, identical calcium transients produce *larger* ΔF/F post — a false "sensitization" signature. Mitigations: make event frequency (offset-robust) the primary metric; for amplitudes, report absolute ΔF alongside ΔF/F, track per-fiber F₀ pre vs. post and report it, and rely on the opsin-negative/light-only control group to bound bleaching effects. Correlation-based ROI clustering and event *detection* are essentially unaffected by a static offset (it only adds shot noise).

**No unmixing is practical** with one green detector; if a cleaner structural image is ever needed, a short stack at a longer excitation wavelength (favoring mCitrine over GCaMP) can approximate one, but the low-percentile projection is usually sufficient. One more line for the methods: 920 nm imaging light can weakly cross-activate red-shifted opsins like ReaChR; this is constant across pre/post and shared with controls, but worth stating.

## Addendum 3: Python front end (afferent2p) replaces the MATLAB unpack/register scripts

Decision (Sep 2026): switch the front end to Python. Audit of the legacy code found that (a) UnpackSBX's settings (binT etc.) only affect preview tifs — the MATLAB registration read raw .sbx, so those settings never mattered for analysis; (b) most spreadsheet columns were never read by ParseDataTable (only Mouse, Date, FOV, Ref, VascChan, Edges, CSD Run; the Runs column was ignored — runs came from folder discovery — and Ztop/Zbot were swapped in the code); (c) UnpackSBX's output folders (001/002/…) never matched the `<Mouse>_<Date>_FOV<N>_run<R>` convention ParseDataTable required, hence manual renaming.

The replacement, `afferent2p`, is one YAML config + `python run_pipeline.py config.yaml`: reads .sbx via sbxreader, converts to tiff, registers all runs together to one reference with Suite2p (rigid+nonrigid, CPU or GPU), exports registered per-run tiffs for AQuA2 (`aqua_input/`), writes Suite2p ROIs/traces + Fall.mat (compatible with the lab's GCAMP_concat_Fall), reads the wheel quadrature into still/moving state, produces QC (pre-vs-post mean-image correlation as a z-drift score, projections, shift traces), and runs a first-pass pre/post per-ROI event-rate comparison using the Blaeser-style event definition, gated to still periods. Verified end-to-end on synthetic Scanbox-format data. To verify on first real use: the .quad file format (loader is best-effort until pinned to a real file) and wheel calibration (counts_per_cm). Single-plane, single-channel for now; optotune extension goes in convert.py.
