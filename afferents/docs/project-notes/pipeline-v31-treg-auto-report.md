## Treg (spontaneous) paradigm — checked and adapted
- Planner/analysis were already paradigm-aware: one experiment per FOV (`<mouse>_FOV<k>_days`), runs 001/002/003 = FOV1/2/3 of each day, conditions `d<date>`, earliest day = baseline. `aqua_analyze` verified on a fake 2-day × 3-FOV folder built from real 2608-1 result files; summary/effects figure now label every day of a multi-day experiment (`d260911 = day -1 (before Treg); d260918 = day 7` from `day_labels.csv`).
- Tuning: `choose_movies(..., per_condition="auto")` takes one movie per day and FOV for a spontaneous mouse (first pre run per day/FOV for optostim); CLI `--per-day`, `--baseline-only`; GUI "movies" box.
- **One common setting per FOV** (`tune.recommend_common`): among the grid settings scored on every day of the FOV, the highest mean recall whose false-alarm share is ≤ max-false on EVERY day (on-fibre rule as before; best common trade-off flagged "rule not met" when none passes). The report prints it after the per-day table; `--apply` writes it as `aqua_opts\<experiment>_Opt.csv` — always for an experiment that spans days (Treg), by default for optostim too (`--per-day-settings` / untick "one common setting per FOV" for per-day files). `report()` now returns `{written, not_applied, rule_not_met, scored, chosen}`; `aqua_tune.py --progress` / `sweep_progress()` count done/failed/pending jobs.
- Batch: a run whose FOV settings file is newer than its `_AQuA2.mat` is queued again automatically (the shipped default is exempt — its mtime means nothing); tab 2b "4 Rebuild batch" no longer forces overwrite. `build_mouse(..., stats=dict)` returns counts; the manifest run entries carry `queued`.

## Step 7 — the report (`aqua_report.py` / `afferent2p/report.py`, GUI tab 7, Auto step 9)
One self-contained HTML per animal, `aqua_analysis\<mouse>_report.html` (10–60 MB, figures base64, lightbox zoom; print to PDF from the browser). Nothing is recomputed — it restates Step 6's tables/figures and reads the per-run files + movies for the evidence. User's choices (Oct 11): HTML, animated clips + montages, montages for ALL events.
1. **Result**: table per experiment (Day · FOV, baseline/condition, events + minutes + rate per condition, **rate difference, raw ratio with its exact 95 % interval and a "few events" flag, modulation index**, still-only, running-only, pupil-matched, speed-matched with "not comparable", adjusted with 95 % CI, common region) + a rule-based **verdict sentence per experiment** (`_verdict`, scale-aware: counts and the interval decide; see "Scale" below) + the **"on one scale" paragraph and `_rates.png`**, then effects / timecourse (+ timecourse_summary table) / speed-tuning figures.
2. **Per experiment**: run table from run_summary.csv, overview (shared y axis) / cfu_map / maps / pupil figures, that experiment's chunk of summary.txt (collapsible).
3. **Evidence per recording** (`load_run`): detection map = AQuA2 `_meanimg.tif` with every `_AQuA2_events.csv` box (blue kept / red dashed noise-CFU / grey dashed excluded-frames, numbered) + CFU outlines (0.3 × max contour, red dashed if rejected); raster = running speed, pupil, event lanes (bars = duration, excluded frames shaded, lanes for overlapping events); clips = GIF per up to 6 kept events spread over dff_max (crop ×k to ~220 px, orange box while the event lasts, label "#id ±s"); montage per event = 7–9 frames (t0−3, t0−1, onset…t1, t1+2, t1+6) cropped around the box (half-size 26–90 px) with the box, plus the box's dF/F (F0 = 20th percentile of the box trace over the whole movie) and a running-speed strip; caption with onset mm:ss, duration, AQuA2 peak dF/F, area, px, CFU, status. Kept/dropped status: kept = in `events_<exp>.csv`; "noise CFU" if its CFU is in the (non-stale) curation; "excluded frames" via `_frames.csv`. Coordinates: export boxes are 1-based in AQuA2's crop; raw-frame = value − 1 + crop offset (`tune.crop_offset` template match of `_meanimg.tif` in the raw mean projection, else centred).
4. **Settings and tuning**: per experiment the settings file name and thrARScl/minSize/minDur/maxSize/smoXY/medSmo/sigThr/sourceSensitivity/registrateCorrect/bleachCorrect/regMaskGap from the manifest presets; the sweep's "->" lines, figure and full text if `aqua_tune\` exists.

## Scale — the user's Oct 11 objection ("raw numbers; sham looks like an effect; high-baseline runs hard to compare")
Looking at the 2608-1 report: 1 → 10 events read ×10 (3.3 mW FOV2), 51 → 144 read ×2.8 (max power FOV2), 0 → 8 (sham FOV2) had no ratio but a big bar in its overview panel. Added to Step 6 (`aqua_analyze.py`: `poisson_rate_ci` (Garwood), `rate_ratio_ci` (exact conditional binomial for two Poisson rates; infinite upper bound without baseline events), `change_measures`, `describe_change`): per comparison in `experiments_summary.csv` `n_events_baseline/condition`, `delta_rate` (events/min — the one measure on the same scale), `ratio_ci_lo/hi`, `log2_ratio_pc` (pseudo-count 0.5 events, defined for every experiment), `modulation_index` ((rc − rb)/(rc + rb), −1…+1), `low_counts` (< 10 events in total or < 3 in a condition = too few to SIZE the change; the direction may still be clear), `rate_*_ci_lo/hi`. `summary.txt` gets a "scale:" line per comparison. Figures: new `<mouse>_rates.png` (every condition of every experiment on ONE rate axis with Poisson intervals + single runs; below, the change as log2 ratio with pseudo-count and the exact interval, dashed when open-ended, hollow + count label when too few); `effects_figure` draws the raw ratio with its interval (arrows beyond the 0.08–12 axis), keeps zero-baseline experiments as hollow pseudo-count markers and labels the counts; the per-experiment overview rate panels share one y axis over the animal (figures drawn after the loop) with Poisson bars and event counts. Report: table columns Difference / Raw ratio (interval, "few events" chip) / Modulation index, an "On one scale" paragraph + the rates figure before the effects figure, and the verdict now says e.g. "1 → 10 events: the increase itself is unlikely to be chance, but on so few events its SIZE cannot be compared with a well-sampled experiment — read the rate difference, not the ratio". For 2608-1: sham FOV2 0 → 8 (+0.26/min, interval 1.71–∞, few), 3.3 mW FOV2 1 → 10 (+0.30/min, ×10, 1.45–441, few), max-power FOV1 3 → 8 (+0.16/min, ×2.7, 0.64–15.7, includes 1), max-power FOV2 51 → 144 (+3.0/min, ×2.84, 2.05–3.99). Not done (mentioned as possible): normalising by fibre area per FOV. GUIDE Step 6 "Scale" paragraph, GUI tab 6 text updated.
