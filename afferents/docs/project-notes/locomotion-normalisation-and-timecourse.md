# Locomotion "normalisation" and the time course after stimulation (v30, Oct 5 2026)

User's two questions (Oct 5): (1) the overall goal is pre vs post stimulation, but locomotion drives afferent activity and in some sessions the animal runs the whole time or not at all — how to address or normalise it; (2) in the RearChr paradigm the FOVs alternate, so the time after stimulation differs per run — add an analysis of the effect's duration/characteristics over time.

## Answer given

**Locomotion.** Three tools in order of what they need: matched-behaviour comparison inside speed bands with an explicit overlap number (model-free; new), the Poisson regression (existing `ratio_adjusted`; interpolates within the overlap, extrapolates outside it), and the design (nothing downstream fixes conditions that never visited the same state). New in `aqua_analyze.py` / `afferent2p/statematch.py`: bins sorted into still / slow / medium / fast (terciles of the running bins' speed, per experiment); per condition and band the minutes and rate (`speed_bands.csv`, `<mouse>_speed_tuning.png`); **matched-speed ratio** = band rates combined with fixed weights (pooled minutes per band) over bands both conditions have ≥ 1 min (direct standardisation) → `ratio_speed_matched`; **behaviour overlap** = share of each condition's minutes in shared bands → `behaviour_overlap_baseline/condition`, `behaviour_comparable` (< 50 % → "NOT COMPARABLE", no ratio printed). On the animal: max-power FOV2 ×2.90 (overlap 97 % / 89 %; slow ×3.4, medium ×3.7, fast ×1.6), max-power FOV1 ×4.76 (100 %/100 %, 3 vs 8 events), 3.3 mW day NOT COMPARABLE (post overlap 27 % and 33 %: pre still 26/31 min, post medium/fast 20–22/31 min), sham FOV2 overlap ok but 0 pre events.

**Time course.** New `afferent2p/timecourse.py`: every run on the day's clock. Clock = mtime of the `.sbx` next to the movie (fallback `_quadrature.mat`, `.mat`, then `run_times.csv` with `run,end[,start]`, else "ESTIMATED" with assumed gaps `--assumed-stim-gap 73`). Real timestamps found on samson: runs 16–17 min apart; first post run started 73 min (260911), 49 min (260917 sham), 74 min (260921), 77 min (261002) after the last pre run ended; post runs span 65 min; post-run centres ≈ 8, 24, 41, 57 min after the first post recording. Outputs `timecourse_runs.csv`, `timecourse_bins.csv` (2-min, `--bin-min`), `timecourse_steps.csv` (consecutive same-field runs: pre→pre, pre→post, post→post), `timecourse_summary.csv`, `run_times_found.csv`, `<mouse>_timecourse.png` (top: rates on the session clock + running fraction; bottom: ratio to the field's pre rate vs minutes since first post recording, log, fitted slope). Per day: post slope (Poisson, per-field intercepts, ×/10 min, block-bootstrap CI, also behaviour-adjusted; < 30 post events flagged weak), second vs first post run, step at the stimulation vs the largest within-condition consecutive change. Day labels from `<mouse>\day_labels.csv` (`day,label`) or `--day-label 260917=sham` appear in summary/figures (written for this animal: 260831 test run, 260917 sham, 260911 2 Hz 3.3 mW, 260921 2 Hz max power).

**Key finding on NavRearChrTIGRE-2608-1 (changes the reading of the headline result):** max-power FOV2 run by run 0.70 → 2.56 → 2.19 → 7.05 /min (×3.7 pre→pre, ×0.86 across the stimulation, ×3.2 post→post); post slope ×1.33 per 10 min (CI 0.98–1.85; adjusted ×1.19); late vs early post run ×2.80. So the pooled ×2.8 is a day-long rising trend as much as a stimulation effect; the step across the stimulation itself is < 1. 3.3 mW day: post slope ×0.48/10 min on 11 events (weak; events in the first post run of FOV2 only). Sham: too few events. Reported in the Claude doc (new Effect 8 + matched-speed subsection under Effect 3; "In short" and caveats updated) and the HTML report.

## Design advice given
Record pre and post in overlapping states (wait for quiet phases / run long enough for both states), a sham day with the same fields and enough baseline events as the drift reference, note the clock time when the stimulation ends, consider a longer post period or a second post block to follow the build-up.
