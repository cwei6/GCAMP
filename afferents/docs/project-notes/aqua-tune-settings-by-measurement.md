## What is swept (user's question Oct 11: "not just the location but the AQuA settings?")
Yes — AQuA2's detection parameters, by default `thrARScl` (1.5/2/2.5/3/4) × `minSize` (50/100/200) plus the current setting; each setting is a complete AQuA2 run (all steps) with the other 45 parameters taken from the base Opt file; any of the 47 variables can join the grid (`--grid sigThr=3,3.5,4`, `--grid maxSize=inf,1500`), at the cost of 3 runs per extra setting. Not a joint optimisation of everything: a grid over the chosen variables. The fibre mask is never given to AQuA2 — it only places the injected transients and decides which detections count as on-fibre in the scoring. Later-stage parameters (sigThr, maxDelay, sourceSensitivity) decide how a detected region is split rather than whether it is found, which injected-transient recall cannot judge well; add them to a second, smaller sweep when the first suggests a specific problem (vessel regions swallowed → maxSize; odd splitting → sigThr).

## Plain-language version (as told to the user, Oct 6)
One movie per day and field (the first pre-stimulation run; v31: for a Treg mouse the first run of every day of the FOV). Two altered copies: a NULL copy (every pixel's trace shifted in time by its own random amount — same noise and brightness, but neighbours no longer rise together, so anything AQuA2 finds there is a false alarm) and an INJECTED copy (the real movie plus 72 artificial afferent-like transients of known brightness, size and duration pasted onto the fibres at known places and times). AQuA2 runs every grid setting on all three copies overnight; per setting the report counts, on the fibre mask only: events/min on the fibres, null events on the fibres as a share of those (false-alarm share), the share of injected transients recovered (recall, by amplitude and duration), plus the off-fibre event rate for information. Chosen: highest recall among settings with false-alarm share ≤ 10 % and ≥ 80 % of events on fibres; per day, with a cross-day comparison per field and (v31) one common setting per field; apply → Opt files → rebuild batch → re-run AQuA2.

## Where the fibres are (user's question "do I need to input anything?", Oct 6) — no input needed
`tune.injection_mask()`: ridge (tube) filter of `spatial.fibre_mask` on the run's mean projection (`_meanproj.tif`, the mean of all frames; 150 frames if missing) — thin bright line-like structures 0.8–2.4 µm wide, z > 3 above the local background, brighter than the median, specks < 20 µm² dropped — then `_elongated_only()` removes round compact pieces (connected pieces must be ≥ 10 µm long and ≥ 2.5× longer than wide; on the real 260921_008 mean image 48–50 "round specks" — the bright puncta / likely autofluorescent dots — are dropped, 52 k px remain); if < 5000 px the ridge threshold is relaxed to z > 2 (kept if ≥ 1500 px); last resort the brightest 5 % of the smoothed, flattened mean image. What it still includes: elongated vessel-wall edges and dura strands (elongated bright lines); what it misses: out-of-focus/very dim fibres. The result is written as `aqua_tune\<run>\fibre_mask_raw.png` (orange outline over the mean image) and `.npy` — the user should look at it once per field. Hand-drawn override (`tune.manual_mask`): `<run>_bin31f_1p98s_fibre_mask.tif` next to the movie, or `FOV<k>_fibre_mask.tif` in the animal folder (any non-zero pixel = fibre; same size as the raw frame, e.g. drawn in ImageJ on `<run>_meanproj.tif` → Edit → Selection → Create Mask); it always wins over the saved automatic mask; a changed mask regenerates the injected movie + truth and moves the old `sNN\inject` result folders to `stale_<date>_inject\`. The mask only decides where the fake transients go and which events count as on-fibre — it does not change what AQuA2 detects. Example mask figures were sent to the user (260921_008 and the dim 260831 field).

## Autofluorescence / activity off the afferents (user's question, Oct 6)
Metrics made fibre-restricted the same day: the fibre mask lives in the RAW frame (the plan's `fibre_mask_raw.npy`, dilated 3 px); each variant's exported mean image gives that variant's own crop offset (the null movie has no motion → smaller crop than the real one, e.g. 502×786 at (5,5) vs 499×782 at (5,7) in the test) and events are mapped back to the raw frame before the mask test. New per-setting fields: `n_real_on`, `rate_real_on`, `rate_off`, `on_fibre`, `n_null_on`, `rate_null_on`, `false_share_on` (= null-on / real-on); `recommend` and the figure use `false_share_on` when present (`T.false_key(rows)`), else `false_share`. Table columns: on-fibre/min, off-fibre/min, null-on/min, false%(on), on-fibre, recall, r0.1/0.2/0.4, short/long. Consequence: off-fibre fluctuations (autofluorescent cells/debris, vessel walls, dura) neither help nor hurt a setting — they appear as the off-fibre rate and lower the on-fibre fraction; autofluorescence ON a fibre bundle is indistinguishable from an afferent event here (left to the CFU curation of Step 5; the injected transients are afferent-shaped, so recall never rewards other shapes). Limitation unchanged: the null movie measures pixel-noise false alarms, not motion artefacts.

## Parallel sweep (user: "MATLAB uses little of the PC", Oct 6)
AQuA2's own code has `parfor` in a few steps (registration cross-correlation, acDetect, F0 fit) but is single-core most of the time, so the gain is at the job level. `run_aqua_tune.m` is now a driver: `nWorkers = {n}` from `--workers` / GUI field "MATLAB jobs at once" (0 = auto: with the Parallel Computing Toolbox `min(6, floor(numcores/2))` capped by free memory / 8 GB via `memory`; 1 = serial; N = N). With the toolbox: `parpool(N)`, `addAttachedFiles(tune_one_job.m, tune_worker_init.m)`, `parfevalOnAll(@addpath, tuneDir)` + `parfevalOnAll(@tune_worker_init, aquaDir)` (cd + `run('startup')` per worker), then `parfor jj = 1:numel(jobList)` → `tune_one_job(j, jobs, paramsCsv, nJobs, aquaDir)` (the former loop body as a function file: skip if events csv exists; aqua_cmd_batch in try/catch → FAILED.txt; export mean image + events csv; delete .mat, rising maps, xlsx). Without the toolbox it says so and runs serially; alternative for any MATLAB: `run_aqua_tune_<k>ofN.m` (sets `tuneSplit = [k N]`, runs the main script, which then takes jobs k:N:nJobs, serial, its own `tune_log_<k>ofN.txt`) and `run_aqua_tune_parallel.bat` (N × `start "" matlab -batch "run('...')"`; needs `matlab` on PATH, else open N MATLAB windows). Each job ≈ 6–8 GB peak (475-frame 500×784 movie); network drive Z: I/O ~1.2 GB written + 0.4 GB read per job. The progress check's per-job time is wall-clock (mtime gaps), so its "hours left" is right with parallel jobs too. The user's first real sweep (Oct 6–7) ran with 2 processes, ~4 h for 6 movies.

## What --plan writes (`<mouse>\aqua_tune\`)
- Per chosen movie (default: the first baseline run of every day and FOV, or one per day and FOV for a Treg mouse; `--days 260911,260921`, `--runs 260921_002`, `--one-per-fov`, `--per-day`, `--baseline-only`): `<run>\` with `fibre_mask_raw.npy/.png` (injection mask on the mean projection), `<stem>_null.tif`, `<stem>_inject.tif` (~390 MB each, ImageJ-style like unpack_bin's tiffs, 30 s per movie), `<stem>_inject_truth.csv`, `settings.json`.
  - NULL movie: every pixel's time series circularly shifted by its own random offset (T/4..3T/4) — same per-pixel values, noise and drift, no spatial coherence → every event AQuA2 finds is false. Limitation: motion artefacts are coherent across pixels and are not in it → the false-alarm share is a lower bound (pixel-noise false alarms).
  - INJECTED movie: the real movie + 72 synthetic transients on the fibre mask (≥ 25 px apart, ≥ 20 px from the border), 4 per class of amplitude 0.1/0.2/0.4 dF/F (of the pixel's own median baseline, i.e. AQuA2's dF/F convention incl. the digitiser offset) × footprint 80/200/400 px grown along the fibre (radius cap 40) × kind short (4 frames above half amplitude: rise 1, plateau 1, tau 2) / long (12 frames: rise 2, plateau 6, tau 6). Calibrated to the 237 detected real events of 2608-1: max dF/F p10/50/90 = 0.11/0.26/0.43; area 145/363/1161 px; duration 50 %-50 % 3/7/31 frames (IQR 4–14). Truth table: 1-based frames, 0-based raw-frame pixel coordinates. AQuA2 grows the footprint 2–3× and reports ~half the nominal dF/F (`--amplitudes 0.3,0.6,1.0 --sizes 200,400,800` brackets the real events it reports at 0.15–0.5).
- `parameters_for_tune.csv` (one Preset column per distinct setting across movies, deduped; AQuA2 47-row layout), `batch\job_NNNN.csv` (one row each: input, preset, outputPath = `<run>\sNN\<variant>\`), `tune_jobs.csv` (job, run, variant, setting, preset, paths), `tune_manifest.json`, `run_aqua_tune.m`, `tune_one_job.m`, `tune_worker_init.m`, and with workers ≠ 1 `run_aqua_tune_<k>ofN.m` + `run_aqua_tune_parallel.bat`.
- Default grid thrARScl 1.5/2/2.5/3/4 × minSize 50/100/200 (+ current) = 16 settings × 3 variants = 48 jobs per movie; `--grid sigThr=3,3.5,4` adds variables. 6 movies ≈ 288 jobs ≈ 7 h at 1.4 min/job serial (measured batch speed on the user's PC), ÷ N with N jobs at once.
- Re-running --plan keeps earlier movies and their finished jobs (manifest merge; movies whose null/inject tiffs were deleted by `--delete-movies` stay in the report, nothing new queued for them); result folders whose `settings.json` is missing or differs from the new settings are moved to `stale_<date>\` so nothing is read under the wrong setting number.

## --report (tune_recommendation.txt, tune_report.csv, <mouse>_tune.png)
Per movie and setting (see the fibre-restricted fields above): recall overall / per amplitude / per size / short vs long, corrected for coincidence with the real movie's own detections ((hit − coin)/(1 − coin); greedy one-to-one match: onset within [t0 − 2, t0 + 6] frames or detection spanning the onset, truth centre inside the detection box + 4 px or within 15 px of its centre; truth mapped into each variant's own crop). Injected transients outside AQuA2's crop are dropped from the recall.
Rule: highest recall (or `--target-amp 0.2` recall) among settings with false-alarm share on the fibres ≤ `--max-false` 0.10 and on-fibre ≥ `--min-on-fibre` 0.80 (on-fibre rule skipped if none reaches it). If nothing passes: the best trade-off (max recall × (1 − false share)) is shown, marked "rule not met"; `--apply` skips it, `--apply-all` writes it. For a FOV recorded on several days: every day's recall/false share at each day's chosen setting ("one setting for every day?") and, **v31, one common setting** (`tune.recommend_common`: among the settings scored on every day, the highest mean recall with false share ≤ max-false on EVERY day; best common trade-off flagged otherwise). `--apply` writes `aqua_opts\<experiment>_Opt.csv` (Name,Variable,Type,Value,Notes; note in the thrARScl row) — the common choice for an experiment that spans days (Treg: `<mouse>_FOV<k>_days`) and by default for optostim too (`--per-day-settings` for each day's own); `find_opt_file` uses these files first. `report()` returns `{written, not_applied, rule_not_met, scored, chosen}`. `--delete-movies` removes the null/injected tiffs after scoring.
Figure: per movie 4 panels — recall vs thrARScl (one line per minSize), recall by amplitude and duration (at the chosen minSize), false-alarm share on the fibres, events/min on the fibres (circles) and off (triangles, dotted) with the on-fibre fraction (squares, right axis); red dotted = current setting, black line/star = chosen; day labels from `day_labels.csv`.
