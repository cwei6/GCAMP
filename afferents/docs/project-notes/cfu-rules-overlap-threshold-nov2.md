# CFU rules: which AQuA2 definition the pipeline uses, and why the overlap threshold is 0.3 (Nov 2–3, 2026)

Figures on samson: `D:\2photon\Chao\GCAMP_affrerents\Claude outputs\cfu_rules_nov2\` (`260911_001_cfu_rules_compared.png`, `overlap_threshold_all_runs.png`, `overlap_threshold_optimisation.png`) and `Claude outputs\curation_preview_nov3\` (2608-1 at 0.3 as the curation window shows it; 260911_001 before/after). Pipeline docs: GUIDE.md "CFU rules (v41)" (incl. the v42 check) and Step 6 "After a CFU re-run (v43)". Progress/continuation: `claude/v34-progress.md` (Nov 2–3 sections).

## The question

While curating NavRearChrTIGRE-2608-1 260911_001 the user found, inside one blue-circled spot, seven overlapping one-event CFUs (events 1, 2, 5, 22, 50, 51, 52) and asked whether they are distinct units or one. Their rule for the answer: **no merge strategy of our own** — use AQuA2's CFU rules, since the tool is cited; if AQuA2 says the same unit, merge; if it says different, treat as different; if it is only a matter of AQuA2 settings, tune the setting. CFU min events stays 1 (every event forms a unit).

## What AQuA2's rules are

**Published rule** (the AQuA2 paper; the mid-August 2026 copy on samson, `H:\MATLAB\AQuA2`): every event gets a duration-weighted footprint (pixel weight = fraction of the event's frames in which the pixel was active, `cfu.CFU_tmp_function`); the overlap of two events is the weighted intersection over union; events whose overlap exceeds the **overlap threshold** join one unit by single linkage (`cfu.hierarchicalClusteringMinMeasure`); a unit needs **min events** events. AQuA2's defaults: 0.5 and 3. With these, the seven events are seven units: their pairwise overlaps are 0.13–0.46 — the footprints of repeated bouton events differ in extent, so the weighted Jaccard never reaches 0.5. Across the three RearChr animals, 97 % of all units were single events (3,860 events in 3,697 units).

**Newer rules** (GitHub `cfu/algo` branch, commits 24 Aug – 14 Sep 2026, in the release of 9 Oct 2026): after the same clustering, (a) `cfu.refineSpatialCFUs` cuts every cluster into watershed basins of its weight map (Gaussian σ 1 px, peak prominence 0.12, min height 0.3, saddle drop 0.2, basin coverage 0.5 — all hard-coded), events joining every basin they cover; (b) `cfu.mergeSimilarCFUs` / `iterativeMergeSimilarCFUs` merges units that touch after a 1-px dilation when their movie-derived dF/F curves correlate at r ≥ 0.85 + 0.15 × the GUI's "Post-merge correlation" control (default 0.5 → 0.925) and their positive AUCs are within a factor 2, complete linkage, up to 5 rounds, siblings of one cluster excluded. The CFU result became a struct array (`cfuInfo1` with id, eventIds, weightMap, occurrence, meanCurve, meanDff, timeWindow, nonTimeWindow, frequencyStats, grayEventIds, spatialClass, isManual, parentId, memberships). Event detection is unchanged (verified by git diff).

Test on 260911_001 with the release installed as `GCAMP_affrerents\AQuA2_2026-10` (same 53 events): the post-merge joins exactly {1, 2, 5, 50, 51, 52} and leaves 22 apart — but the basin splitting turns 53 events into **154 units**, 28 events sitting in 2–13 units each (event 7 → 10 units, event 11 → 12), so a unit no longer equals a set of events and one event is counted several times. **Not adopted.**

## The decision

Published rule, **overlap 0.3**, min events 1 — the one documented setting changed, nothing else. Reasons, all on the whole dataset (96 runs of 2608-1 / 2608-2 / 2609-1, their 3,697 units at 0.5, 10,429 overlapping unit pairs):

1. The pooled distribution of overlaps falls off smoothly from 0 to 0.5 with no gap — the threshold cannot be read off the data, it has to be chosen by a criterion (`overlap_threshold_all_runs.png` A).
2. Unit counts vs threshold: 0.4 keeps 88 % of the units, 0.3 keeps 70 % (2,571), 0.2 keeps 52 %; the three animals behave alike (B).
3. Optimisation (`overlap_threshold_optimisation.png`): every overlapping pair was labelled without using the overlap — *same place* when the two events' weighted centres lie within half the smaller event's equivalent radius of each other (AQuA2's "consistent spatial foundation"; 1,954 pairs), *two places* when each centre lies outside the other event's extent (4,633 pairs), the rest unscored — and for every threshold each recording was clustered exactly as AQuA2 does (single linkage, chains included). The agreement of the resulting units with the labels (F1) peaks at **0.3 pooled** (0.275 in 2608-1 and 2608-2, 0.3 in 2609-1); Youden's J at 0.275–0.3. At 0.3, 74 % of same-place pairs end up in one unit and 8 % of two-place pairs do; at 0.2 the chains pull 44 % of two-place pairs together (pair by pair 0.2 looks best, which is why the clustering has to be evaluated, not the pairs); at 0.5, 0.4 % of the repeats are joined. The optimum is stable for the label variants tried (half radius, full radius, ± co-activity as a negative).
4. What merges at 0.3 is compact: centres of a merged group a median 3.5 µm apart (90th percentile 10 µm), 7 % of groups wider than 12 µm; at 0.2: 5 µm / 19 µm / 20 %, groups of up to 27 events (`overlap_threshold_all_runs.png` C, D).

For the circled spot: {1, 2, 5, 50, 51, 52} become one unit, 22 stays separate (it overlaps the others by 0.13–0.20 and is co-active with 5) — the same grouping the newer AQuA2 rules found independently. In 260911_001 the only other change is 6 + 41 (one bouton firing twice, frames 1–78 and 72–95): 53 → 47 units. **Confirmed on the re-made result (Nov 2, 19:43): 47 units, multi-event units {1,2,5,50,51,52} and {6,41}; AQuA2's own overlap values (`_cfu_pre.mat`) agree with the Python computation of the pooled analysis to 3e-8.**

Methods sentence: *"Consensus functional units were defined with AQuA2's overlap clustering of events (single linkage on the duration-weighted footprint overlap); the overlap threshold was set to 0.3 (AQuA2 default 0.5), the value at which the clustering best reproduced same-location repeats across all recordings of the three animals, because bouton events of varying extent overlapped only 0.25–0.45. Each event forms a unit (min events 1)."* Run the final pre/post statistics once at 0.5 as well (uncurated) to show the conclusion does not hinge on it; event rates per minute do not depend on the threshold at all — only unit counts, events per unit and the unit-matched measures do.

## Per recording? (asked Nov 3 after checking with a colleague: "0.3 is a good number to start — could it be fine-tuned automatically per recording?")

No — and the reason is in the data, not in preference. The criterion needs same-place and two-place pairs; only 21 of the 96 recordings contain 20 or more same-place pairs, 30 contain no overlapping pair at all, and for the other 45 the per-recording "optimum" is noise (19 of them land on 0.1, the lowest value tried = a flat curve). The 21 informative recordings give 0.15–0.375, median 0.275 — sampling noise around the pooled value. A per-recording threshold would also give the pre and post runs of one FOV different unit definitions, the objection the user raised for the detection settings. Per day × FOV (pre + post together) it is estimable in 11 experiments: optima 0.2–0.35 (0.2, 0.25, 0.25, 0.275, 0.275, 0.3 ×5, 0.35), and the fixed 0.3 reaches a median 95 % (never below 93 %) of each experiment's own best — the gain of adapting is a few percent, the cost is a different unit definition per day in a comparison across days. **Decision: one threshold per dataset (0.3) + an automatic CHECK, no adaptive mode.** The check on the re-made results (Nov 3) said OK for every judged experiment of all three animals, best 0.3 pooled in each — so 0.3 applies to every run; the user confirmed CFU min events 1.

## What was built

**v41 (Nov 2)**
- The CFU batch applies the published rule with the pipeline defaults 0.3 / 1 (`aqua_batch.CFU_OVERLAP_DEFAULT`, `CFU_MIN_EVENTS_DEFAULT`; tab 4 fields, `--cfu-overlap`, `--cfu-min-events`), runs with the AQuA2 copy of the top row, prints which rules it is running, removes any other AQuA2 copy from the MATLAB path (two copies' `+cfu` packages merge otherwise — on samson it found and removed `AQuA2_2026-10` and `H:\MATLAB\AQuA-master`), and redoes every result whose saved `cfuOpts` differ from the current values or that was made by the other rule set. An AQuA2 copy with the newer rules can be named explicitly ("Other AQuA2 copy for the CFU step only", `--cfu-aqua`, post-merge control `--cfu-merge`) — then its rules apply and the output says so.
- `read_cfu` reads both result layouts (cell before 1 Sep 2026, struct array after) and reports the rule a file was made with (`rules`, `cfu_rules_of`); the curation window shows it in the title; the report's section 9 states the rule read from the result files and warns when runs mix rules.
- On samson: `aqua_batch\run_cfu_batch_v41.m` per animal and the one-paste driver `D:\2photon\Chao\GCAMP_affrerents\run_cfu_v41_all.m` (all three animals, log `run_cfu_v41_all_log.txt`); the batches rebuilt by the v41/v42 GUI produce the same script as `run_cfu_batch.m`.

**v42 (Nov 3) — the overlap-threshold check** (`afferent2p/cfu_overlap.py`, `cfu_overlap_check.py`, tab 4 "Check the overlap threshold (from the CFU results)", report section 9)
- The CFU batch writes next to each result `<run>_AQuA2_cfu_pre.mat`: AQuA2's own pairwise event overlap table (`cfu.CFU_tmp_function`'s `s_t0`) + per event the duration-weighted centre, footprint size, first/last frame (2–10 KB; in a try/catch, never stops the batch).
- The check labels every overlapping pair without the overlap (same place = centres within 0.5 × the smaller equivalent radius; two places = each centre outside the other's extent), clusters each recording as AQuA2 does at 0.10 … 0.50, and reports per experiment (day × FOV) and pooled: F1 curve, best threshold, F1 at the chosen one, verdict OK (≥ 90 % of the experiment's best) / CHECK / too few pairs (< 30 same-place pairs). Outputs `aqua_batch\cfu_overlap_check.txt / .csv / .png`; the report's section 9 quotes the verdict and shows the figure. It changes nothing.

**v43 (Nov 3) — the curation survives the re-run correctly.** Decisions in `_res_cfu_curated.json` name CFU numbers of one CFU result. Until v42 the pipeline only noticed a redone `_AQuA2.mat`, but the CFU batch rewrites only `_res_cfu.mat` — decisions made at 0.5 would have been applied to the wrong units at 0.3. Now (`aqua_io.curation_stale_reason`) a decision file is stale when the AQuA2 result or the CFU file is newer than it, or when the CFU rules recorded in it (`cfu_rules`, written since v43) differ from the CFU file's; stale decisions are ignored everywhere (curation window, analysis, QC report, status), the window opens such runs clean and says so, and the old file is kept as `_res_cfu_curated_superseded_<date>.json` when the run is next saved. `cfu_curate.py --list` (tab 6 "List CFU results and decisions") ends with "N of M runs with a CFU result are curated under the current CFU rules" — the curation status.

## Consequences for the workflow

Every CFU file of the three animals is redone at 0.3 → the curation done at 0.5 has to be redone; since v43 the window recognises the old decisions as belonging to the earlier result, ignores them and keeps them as superseded files (as of Nov 3 there was nothing to keep: the only two decision files, 2608-1 261016_001 and 2609-1 261014_008, were empty). Unit-based measures change (counts ×0.7, events per unit up); event rates do not. Changing the overlap or min events later redoes the CFU files again and invalidates the curation again — decide once; run the check on a new animal before curating it.
